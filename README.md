# VELORA — luxury e-commerce demonstration

[افتح المتجر مباشرة](https://mohammedalqam.github.io/velora-luxury-demo/) · [المصدر على GitHub](https://github.com/mohammedalqam/velora-luxury-demo)

متجر توضيحي كامل بالعربية والإنجليزية لعرض خدمات تصميم المتاجر. Next.js + React + TypeScript + Tailwind CSS، مع تصدير ثابت لجميع الصفحات. لا توجد API، قاعدة بيانات، تسجيل دخول، بوابة دفع أو معالجة طلبات تجارية.

## التشغيل

يتطلب Node.js 22.13 أو أحدث وpnpm 11.25.0.

```bash
npm install -g pnpm@11.25.0
pnpm install
pnpm dev
```

افتح `http://localhost:4173`. الصور والخطوط محلية؛ لا يحتاج المتجر إلى خدمة مدفوعة أو مفتاح API.

```bash
pnpm typecheck
pnpm test
pnpm build
```

البناء يخرج صفحات HTML وأصولاً ثابتة في `out/`. لا تستخدم `next start` مع هذه النسخة لأنها تستخدم `output: 'export'`.

## ما يحتويه المتجر

- الرئيسية: حملة افتتاحية أصلية، مختارات بتكوين تحريري، قصة العلامة، المجموعات، حملة كاملة، الوصول الجديد والمشاهدات الأخيرة.
- كتالوج أساسي من 24 منتجاً: 6 ساعات، 6 قطع مجوهرات، 6 حقائب، 6 عطور.
- صفحات المجموعة والمنتج، مع البحث بالعربية أو الإنجليزية، الفلاتر، الترتيب، العرض السريع، الخيارات، معرض بزاويتين وتكبير الصورة.
- سلة جانبية وصفحة سلة، كميات محدودة بالمخزون التوضيحي، قائمة مفضلة وحفظ محلي يتحمل البيانات التالفة.
- إتمام طلب تجريبي: طرق استلام، مناطق، رسوم، كود `VELORA10`، وحساب الإجمالي ثم شاشة تأكيد.
- حكاية العلامة، التواصل، سياسة توصيل واسترجاع توضيحية، 404 وحالات التحميل والخطأ.
- وضع عرض مستقل في `/presentation/`، مع اسم مخصص، اختيار المجال، اللغة، ومعاينة داخل إطار بعرض 1440 أو 390 بكسل. الإطار يُصغّر ليناسب مساحة العرض دون تغيير عرض الصفحة الداخلية.
- احترام `prefers-reduced-motion`، تمرير أصلي، نوافذ `<dialog>` أصلية، حالات تركيز واضحة واتجاه RTL/LTR.

## تخصيص متجر جديد

### الهوية والمحتوى

عدّل `src/config/store.config.ts`:

- `name`: الاسم الأساسي. وضع العرض يمكنه تغييره محلياً دون تعديل المصدر.
- `logo`: اتركه فارغاً لاستخدام الشعار النصي، أو ضع مسار صورة محلية مثل `/my-logo.svg`. يظهر الشعار المخصص عند استخدام الاسم الأساسي. `/public/logo.svg` مثال قابل للاستبدال.
- `defaultLanguage`: `ar` أو `en`. العربية هي الأصل.
- `currency`: رمز ISO مثل `ILS` أو `USD`؛ الأسعار أرقام في هذه العملة.
- `announcement`: النص في الشريط العلوي.
- `shipping`: رسوم القياسي والسريع والاستلام، حد التوصيل المجاني، ورسوم المنطقة الإضافية.
- `home`: صورة وعنوان ووصف الافتتاحية، صورة الحملة، وترتيب المجموعات المميزة.
- `contactEmail` و`contactLinks`: روابط تواصل حقيقية عند التخصيص؛ تُترك فارغة في الديمو.
- `socialLinks`: روابط فعلية فقط. لا توجد حسابات أو روابط وهمية افتراضياً.
- `footer` و`demoNotice`: محتوى التذييل والتنبيه.

عدّل `src/config/theme.config.ts` للألوان، الخطوط والاتجاهات البصرية. تُطبّق الألوان الأساسية من هذا الملف على المتجر الرئيسي. القوالب الإضافية تستخدم ألوانها الخاصة، مع بقية رموز التصميم المشتركة. قواعد الحركة والاستجابة في `src/app/globals.css`.

### المنتجات والمجموعات

عدّل `src/data/products.ts`. تتضمن السجلات معرّفات ثابتة، أسماء ووصفاً باللغتين، slug، مجموعة، أسعاراً، صوراً، ألواناً، خيارات بأسعار ومخزون، خامات، تفاصيل، منتجات مرتبطة وقوالب مناسبة.

- لا تغيّر ID لمنتج منشور إن أردت الاحتفاظ بالمفضلة المحلية الخاصة به.
- لكل خيار سعره ومخزونه. لا يمكن شراء خيار غير متاح أو إضافة كمية تتجاوز مخزونه.
- السعر في البطاقة يبدأ من السعر الأساسي؛ تظهر عبارة «من» إذا اختلفت أسعار الخيارات.
- عند تعديل المنتجات أو slugs، أعد البناء لإعادة إنشاء الصفحات الثابتة.
- إن أضفت مجموعة، أضف تعريفها إلى `categories` أيضاً.
- للحصول على عروض وخصومات فعلية مستقبلاً، أضف بيانات موثقة بدلاً من اختلاق أسعار سابقة.

### الصور

الصورة الافتتاحية و24 صورة كتالوج أصلية مولّدة لمنتجات متخيّلة. كل ملف أساسي هو أطلس من صورتين حقيقيتين مولّدتين للمنتج نفسه: أمامية وجانبية/خلفية. CSS يعرض كل نصف مستقلاً؛ لا يوجد عرض 360 مزيف ولا إعادة تلوين لصورة واحدة.

- للأطلس: ملف 3:2 من إطارين 3:4 متساويين، و`duo: true`.
- لصور عميل حقيقية: استخدم عدة مسارات مستقلة في `images` واضبط `duo: false`.
- ضع ملفات WebP في `public/images/`، مع قص متوازن ومساحة مناسبة للمنتج.
- صورة البديل الخاصة بالهوية موجودة في `public/images/fallback.svg`.
- `ASSET_GENERATION.json` يوثّق الأصول المولّدة وملخص الموجّه، و`ASSET_SOURCES.json` يوثّق صور Unsplash المستخدمة في الحملات والقوالب الإضافية.
- بعض الصور التقنية المرجعية قد تحتوي علامات المصنع الظاهرة. هي صور توضيحية، وليست منتجات مصنّعة بواسطة VELORA أو ادعاء شراكة. استبدلها بصور منتجات العميل عند تخصيص متجر تجاري.
- الخطوط محلية بصيغة WOFF2؛ تراخيص OFL مرفقة في `licenses/`.

### القوالب

القالب الأساسي `lifestyle` مكتمل مع 24 منتجاً. الاتجاهات الإضافية:

| الاتجاه   | المحتوى                                          |
| --------- | ------------------------------------------------ |
| `jewelry` | 12 منتجاً من المجوهرات والساعات                  |
| `fashion` | 12 منتجاً من الأزياء والحقائب، ومقاسات للأزياء   |
| `tech`    | 7 منتجات صوتية وتقنية، بمعلومات ومواصفات توضيحية |

تبديل المجال يغير الكتالوج والمجموعات والافتتاحية والهوية، ويُفرغ السلة لتجنب خلط عروض العملاء. المفضلة مرتبطة بمعرّفات المنتجات. وضع العرض محلي فقط؛ تغيير الاسم في متصفحك لا يغيّر النسخة التي يفتحها شخص آخر في متصفح مختلف. لإنشاء نسخة مخصصة لعميل، عدّل ملفات الإعداد والمنتجات ثم انشر نسخة مستقلة.

## النشر

المصدر محفوظ في الفرع `main`. نسخة GitHub Pages الجاهزة للنشر توجد في الفرع `gh-pages`، ومصدر النشر هو جذر ذلك الفرع.

لبناء نسخة Pages:

```bash
pnpm build:pages
```

انشر محتويات `out/` إلى جذر `gh-pages`، بما فيها `.nojekyll` و`_next/`، ثم تحقّق من انتهاء نشر Pages. تغيير `main` وحده لا يحدّث الموقع؛ يجب إعادة البناء ونشر ناتجه أيضاً.

الأمر يضبط `NEXT_PUBLIC_BASE_PATH=/velora-luxury-demo` و`NEXT_PUBLIC_SITE_URL=https://mohammedalqam.github.io`. التنقل والصور ومعاينة العرض تدعم هذا المسار. لا توجد متغيرات أسرار مطلوبة. الصور والخطوط تُنشر مع المتجر.

لاستضافة جذر نطاق آخر، استخدم `pnpm build` دون `NEXT_PUBLIC_BASE_PATH` وحدد `NEXT_PUBLIC_SITE_URL` بأصل النطاق الجديد. عدّل الاسم والوصف وصورة المشاركة في الإعدادات عند تخصيص متجر عميل. الديمو يحمل `noindex`؛ لا تدّعي جاهزية SEO تجارية أو نتيجة Lighthouse دون اختبار.

## البيانات والتجربة التجريبية

- `localStorage` بمفتاح `velora-demo-v1`: اللغة، الاسم التجريبي، المجال، معرّفات السلة وخياراتها وكمياتها، المفضلة والمشاهدات الأخيرة.
- لا تُحفظ أسماء أو عناوين أو رسائل أو معلومات دفع للعميل.
- بيانات العميل في checkout عينات وهمية جاهزة للقراءة فقط.
- `sessionStorage` بمفتاح `velora-demo-order`: المرجع التجريبي والإجمالي وعدد القطع والوقت فقط.
- التواصل يعاين النموذج محلياً؛ لا يرسل رسالة.
- تأكيد الطلب يفرغ السلة ويعرض نجاح المحاكاة؛ لا ينشئ طلباً حقيقياً ولا يحصّل مالاً.
- الصور والمنتجات والمواصفات والأسعار والمخزون بيانات توضيحية. لا توجد مراجعات أو أرقام مبيعات مختلقة أو عدادات ندرة.

## التحويل إلى متجر حقيقي

يلزم قبل التشغيل التجاري: كتالوج ومخزون موثوقان من الخادم، قاعدة بيانات للطلبات، تحقق من الأسعار والكميات على الخادم، حماية الطلبات والإدخال، دفع معتمد وإشعاراته الموثقة، إدارة وشحن واسترجاع، سياسات قانونية مناسبة، ومراقبة وأمان ونسخ احتياطي. هذه الوظائف غير موجودة في الديمو، ولا يجوز اعتبار الحفظ المحلي نظام طلبات حقيقي.

## التحقق

18 اختباراً آلياً تغطي الحسابات، سلامة البيانات، الحفظ، السلة، الخيارات، البحث والفلاتر، اللغة، الطلب التجريبي ووضع العرض. اختبارات التفاعل تعمل في JSDOM، ولا تقيس الرسم أو اللمس الفعلي أو أداء المتصفح.

راجع `docs/QA.md` لمجال التحقق وحدوده. مراجعة المتصفح على الرابط العام تسجَّل في ملف التحقق بعد النشر. لا تُعتبر أهداف الأداء أو جودة كل قياس شاشة مثبتة دون إجراء هذه المراجعة؛ اختبارات Lighthouse منفصلة عن اختبارات JSDOM.
